# Contributing

Thanks for helping improve Understanding Studio. Contributions should improve understanding, reliability, accessibility, or ease of use rather than add production complexity for its own sake.

## Before opening a change

1. Read SKILL.md and references/sources.md.
2. Check existing issues and pull requests for similar work.
3. For a substantial change, explain the problem and proposed approach in an issue first. Small corrections can go directly to a pull request.

## Useful contributions

- Clearer trigger descriptions and prompts.
- Worked examples with explicit assumptions and meaningful interactions.
- Accessibility improvements to the offline template.
- Documented host installation methods you have actually tested.
- Reproducible evaluations of skill triggering and artifact quality.
- Translations that preserve technical meaning and limitations.

## Pull request checklist

- Describe what changed and why.
- State the files and behaviors affected.
- Preserve source attribution and the distinction between inspiration and formal compliance.
- Add no API keys, private conversations, personal information, or copyrighted standard text without permission.
- Keep the HTML template self-contained; do not introduce network or storage dependencies.
- Document checks actually run and checks not run.
- Keep examples clearly labeled as fictional when they use assumed numbers.
- Preserve the existing license and include only material you have the right to contribute.
